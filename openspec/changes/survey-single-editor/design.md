## Context

`device-satisfaction-survey` 已实现多活动：Hub 用活动下拉和「开启新一轮」，选项随整表「保存」一起写入，结果按活动分页。App 只读 id 最大的活动。运维确认不需要分轮，只要一份问卷和一份统计，并且每一行文案要能改、能马上持久化。

开关、上海时区起止、只写意见、提交快照、两条 App 接口不计入 usage，这些不变。

## Goals / Non-Goals

**Goals:**

- 库中只服务一份活动；已有多行并入这一份。
- 选项行单独新增、改文案、改启用、删除，并立即落库。
- Hub 去掉活动维度；右侧列出全部提交。
- 已提交用户不因改文案而再次弹出。

**Non-Goals:**

- 改 App 路径、登录要求、usage 排除。
- 改 Flutter。
- 新增 Redis 或后台任务。

## Decisions

### D1：固定一份活动

- **选择**：读写都通过「确保唯一活动」：没有则插入一条默认关闭的活动；多于一条时保留最小 id，把其余活动的选项与提交的 `campaign_id` 改到该 id，再删除多余活动。App 的已提交判断与 Hub 列表都只看这一份 id。
- **理由**：统计只有一张表；旧数据不会丢。
- **备选**：继续留多行只是藏起下拉 → 已答状态仍按轮分裂，拒绝。

### D2：选项逐行接口

- **选择**：在 `/device/admin/api/survey/` 下增加选项新增、更新文案与启用、删除。新增可带文案；空文案允许暂存，但对 App 不展示。更新立即写库。删除只删选项行，不改已有提交快照。
- **理由**：不把选项绑在「必须先填有效期再点保存」上。
- **备选**：前端自动帮用户点整表保存 → 有效期校验失败时行仍丢，拒绝。

### D3：设置与选项分开保存

- **选择**：开关、起止、说明仍走保存接口，但不再整表替换选项。`end_at < start_at` 或起止缺失时只拒绝这次设置保存。
- **理由**：时间规则保持原样，同时不挡住文案编辑。

### D4：去掉新一轮

- **选择**：Hub 删除活动下拉和「开启新一轮」。`POST /device/admin/api/survey/new` 不再创建活动。
- **理由**：再开一轮会把已提交的人重新算进可弹人群，与「只有一次统计」相反。

## Risks / Trade-offs

- [改文案后已提交用户不再被问] → 接受；快照仍是当时的句子。
- [并活动时两轮都有同一 wx 的提交，唯一键冲突] → 保留提交时间较早的一行，丢掉较晚的重复 wx，并入前先处理冲突。
- [空文案行留在库里] → App 的 current 跳过空文案。

## Migration Plan

- device-service 启动时执行并成单活动。回滚页面时不要再调用已删除的「新一轮」；数据留在保留的那份活动上即可。
