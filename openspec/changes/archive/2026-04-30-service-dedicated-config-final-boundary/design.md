## Context

当前仓库在服务拆分上已具备 `gateway`、`voice-service`、`device-service`、`history-service`、`worker-service` 的进程边界，但配置边界仍不一致：`history-service` 已使用专属配置，`voice-service` 与 `device-service` 仍默认复用主配置。与此同时，主配置仍承载过多领域项，易形成“通过共享配置反向耦合”的路径，影响目标态微服务边界落地。

本次变更目标是完成配置层面的最终收敛：每个 service 使用专属配置文件，主配置只保留网关与全局公共配置，配套收敛运行时环境变量和文档规范，使“服务边界、配置边界、数据访问边界”一致。

## Goals / Non-Goals

**Goals:**
- 为 `voice-service`、`device-service` 建立专属配置文件，并对齐 `history-service` 的加载模式。
- 清理 `config.yaml` 中不属于主服务（gateway）的领域配置，形成“主配置瘦身”基线。
- 统一服务启动入口的配置加载规则、默认值与环境变量覆盖语义。
- 同步更新 compose/kustomize 与运行文档，确保部署形态与配置边界一致。
- 将配置治理与跨服务接口治理联动，避免通过共享配置绕开服务契约边界。

**Non-Goals:**
- 不在本次变更中重写所有业务逻辑实现。
- 不引入配置中心或动态热更新机制。
- 不改造数据库 schema 与消息协议。

## Decisions

1. **按服务一进程一配置文件**
   - 决策：`voice-service`、`device-service`、`history-service`、`gateway-service` 使用各自默认配置文件，均可由 `GF_GCFG_FILE` 覆盖。
   - 理由：最直接体现配置边界，降低跨服务误读配置风险。
   - 备选：继续复用主配置并依赖环境变量覆盖。
   - 不采纳原因：会持续放大“配置耦合导致职责耦合”的问题。

2. **主配置仅保留公共/网关域**
   - 决策：将 voice/device/history 的专属业务配置迁移至各自配置文件；主配置仅保留 gateway 与全局共享项。
   - 理由：防止主配置成为“隐式单体配置中心”。
   - 备选：保留完整主配置，仅在文档约束“不要误用”。
   - 不采纳原因：约束无法替代技术边界，长期易回归。

3. **环境变量覆盖保持服务内聚**
   - 决策：每个服务仅暴露本服务关心的覆盖变量（如 `VOICE_DB_LINK`、`DEVICE_DB_LINK`），避免跨域覆盖命名。
   - 理由：提高可读性与运维可预测性。
   - 备选：继续复用泛化变量命名。
   - 不采纳原因：调试与排障成本高，容易误配。

4. **边界收敛顺序：配置先行，运行验证收尾**
   - 决策：先完成配置与启动入口改造，再做远程契约链路联调验证。
   - 理由：配置是所有运行行为的前提，先稳定再联调可减少噪声。
   - 备选：边改边联调。
   - 不采纳原因：问题定位维度过多，效率低。

## Risks / Trade-offs

- **[配置迁移遗漏导致启动失败]** → Mitigation：为每个服务列出配置清单并逐项比对，增加启动前校验日志。
- **[旧环境仍依赖主配置字段]** → Mitigation：迁移期保留兼容窗口并提供回滚路径，逐环境灰度切换。
- **[文档与实际配置漂移]** → Mitigation：将文档更新纳入任务强制项，与配置改动同 PR 提交。
- **[过度拆分增加维护成本]** → Mitigation：仅拆分服务专属项，共享项保持统一定义。

## Migration Plan

1. 梳理现有 `config.yaml` 字段归属，输出按服务拆分清单。
2. 新增 `config.voice-service.yaml`、`config.device-service.yaml` 并迁移对应字段。
3. 更新 `cmd/voice-service/main.go`、`cmd/device-service/main.go` 默认配置加载路径与覆盖规则。
4. 瘦身主配置，删除不应由 gateway 承担的领域配置项。
5. 更新 compose/kustomize 与运行文档，完成多环境变量对齐。
6. 运行验证：各服务独立启动、跨服务契约调用、回退语义与边界检查项。

回滚策略：
- 服务级回滚到上一版本镜像与上一版配置文件；
- 临时通过 `GF_GCFG_FILE` 指回兼容配置，确保服务可用后再分步修正。
