## Context

问卷已经收成一份。`survey_response` 用 `(campaign_id, wx_id)` 唯一键，有行就视为已答，current 不再展示。Hub 不能把某条结果作废，所以交过的人无法再被问到。

运维要的是改「这条提交还算不算数」，不是再开一轮活动，也不是删掉那一行。

## Goals / Non-Goals

**Goals:**

- Hub 每一行提交可标有效或无效，并立即保存。
- 无效后该 wxId 可以再看到问卷；再提交覆盖同一行并恢复为有效。
- 无效行仍出现在结果列表里。

**Non-Goals:**

- 多份活动、按活动筛选、开启新一轮。
- 改 Flutter 或 App 路径。
- 删除提交行。
- 新的 Redis 读缓存。

## Decisions

### D1：有效列挂在提交行上

- **选择**：`survey_response.valid`，`TINYINT`，`1` 有效、`0` 无效。启动时幂等加列，已有行默认 `1`。
- **理由**：一个人仍只有一行，统计不用拆表。
- **备选**：标无效就删行 → 上次答案从 Hub 消失，拒绝。

### D2：挡住弹出只认有效行

- **选择**：current 在开关与时间窗通过后，仅当该 wxId 存在 `valid=1` 的行才 `show=false`。`valid=0` 与无行一样可以展示。
- **理由**：和 Hub 上的开关同一含义。

### D3：再次提交覆盖无效行

- **选择**：提交时若已有行且 `valid=0`，更新快照、意见、设备号、宝宝昵称、`submitted_at`，并把 `valid` 设为 `1`。若已有行且 `valid=1`，保持原样并返回成功。双空仍然拒绝且不改行。
- **理由**：唯一键不能再插一行；覆盖后 Hub 看到的是最新一次，旧内容被换掉。
- **备选**：无效行保留、另插历史表 → 超出「一份统计」，拒绝。

### D4：Hub 单独接口

- **选择**：`POST /device/admin/api/survey/response/valid`，body 为提交行 id 与 `valid`。结果列表带上 `id` 和 `valid`。
- **理由**：与选项行一样点一下就保存。

## Risks / Trade-offs

- [再次提交会盖掉上一次的选项和意见] → 标无效前 Hub 上仍看得到；一旦用户再交卷，列表变成新内容。
- [旧库没有 valid 列] → 启动时补列，默认有效，已答用户行为不变。

## Migration Plan

- 部署 device-service 后首次启动加列。回滚代码时列可留，旧逻辑会把它当成普通提交行忽略该列。
