## Context

胖宝官网与合规页由 `gateway-app-server` 静态托管（`resource/public/pangbao-home.html`、`privacy-policy.html`、`user-agreement.html`）。路径约定已稳定：`/`、`/privacy-policy.html`、`/user-agreement.html`。当前页脚无公司主体与 ICP；隐私/协议无运营者全称；用户协议仍写「胖宝团队」；iOS 下载仅提示搜索；能力区未覆盖预测提醒、推送、诊疗等现网卖点。App Store 已上架且开发者账号迁至公司，列表页仍可能短暂显示个人名（商店后台），本设计保证**本仓对外页**与公司主体对齐。

已确认常量见 proposal Impact。

## Goals / Non-Goals

**Goals:**

- 三页统一运营主体：杭州彩逗科技有限公司（中英）。
- 官网页脚：ICP、客服邮箱、合规链接；iOS 直达 App Store。
- 隐私政策按现网能力补披露；用户协议去掉「团队」表述并补 IP/付费/AI 要点。
- 保持 URL 不变，客户端无需改加载地址。

**Non-Goals:**

- 不修改 App Store / 华为控制台元数据（版权、开发者显示名）——由运营在后台完成。
- 不新建微服务、不改 gateway 路由逻辑。
- 不做英文全站；英文公司名仅出现在主体披露处。
- 不伪造用户数、融资或虚假背书。
- 不在本变更实现预测文案等业务逻辑（已另有 change）。

## Decisions

### D1. 静态 HTML 直接修订

- **选择**：在三份 HTML 内硬编码已确认的主体常量（公司名、ICP、邮箱、App Store URL）。
- **理由**：无多环境差异需求；改配置成本高于收益。
- **备选**：环境变量注入页脚 — 不做。

### D2. ICP 链到工信部查询

- **选择**：备案号可点击，链至 `https://beian.miit.gov.cn/`（常见做法）。
- **理由**：增强可核验性。

### D3. 注册地址表述

- **选择**：隐私/协议写「注册地址以市场主体公示为准」，不写具体门牌。
- **理由**：产品已确认；避免地址变更反复改页。

### D4. 隐私能力披露范围（本变更必写）

相对现网至少补充或对齐：

1. 运营主体与联系邮箱。
2. 推送：为离线提醒等注册设备推送 token（APNs/HMS/MiPush 等），用户可在系统设置关闭通知。
3. 预测临近：客户端同步待发生时间点至服务端用于叫醒提醒。
4. 商业化：VIP/功能开通相关的订单与权益状态（不扩大收集范围表述）。
5. AI：保留多供应商可配置表述；诊疗/值得留意/成长轨迹等若会发送摘要或提问至 LLM，并列说明；思考过程展示若仍存在则保留。
6. 监护人：宝宝档案由监护人提供。
7. 生效日期更新为修订日（实现时取部署当日或约定日期，如 2026-09-17）。

诊疗「近 7 天摘要」与现行「Go 不缓存摘要」冲突时：**以实现为准写清**——若当前为按需由智能服务处理上下文而非 Go 持久化 7 天摘要，则采用「按需处理上下文、非完整流水 dump」表述，并去掉与实现不符的「必须读取近 7 天聚合摘要」绝对句（同时不违反「可能发送至第三方模型」的披露）。

### D5. 官网能力区

- **选择**：在现有三列能力上增补要点（预测与提醒、诊疗、投屏/协同若文案已有则对齐 App Store 卖点），不新增大段营销墙。
- **理由**：与 [App Store 胖宝页](https://apps.apple.com/cn/app/%E8%83%96%E5%AE%9D/id6774418472) 卖点一致，避免官网过时。

### D6. 页脚去掉运维旁白

- **选择**：删除「官网事件 logo 与 Android 下载链路均来自系统权威数据」。
- **理由**：对用户无信任增益，偏内部实现说明。

## Risks / Trade-offs

- [商店页仍显示个人开发者名] → 运营继续在 App Store Connect / 华为后台更新显示名与版权；官网已写公司可作过渡。
- [隐私写多了与实现不符] → 披露以现网真实路径为准；不确定项用「以产品实际开通为准」收窄。
- [邮箱为 foxmail 个人域] → 已确认使用；正规感弱于企业域，可后续换 `@caidou...` 再改一处常量。
- [ICP 号与域名绑定] → 运营确认号正确；错误备案号比没有更伤信任。

## Migration Plan

1. 合并静态页变更并部署 gateway-app（或统一静态资源发布路径）。
2. 抽检：首页页脚、ICP 链接、App Store 按钮、隐私/协议主体与邮箱。
3. 回滚：还原三 HTML。
4. 并行：商店后台将版权改为公司（若尚未）。
