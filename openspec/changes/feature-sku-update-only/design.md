## Context

`AdminUpsertFeatureProduct` 在 `productCode` 为空时调用 `genFeatureProductCode`，插入 `fp_{功能}_{时间}_{随机}`。管理页打开功能时不把已有行写入 `pCode`，直接点保存就会走新建。「新建套餐（清空编码）」也是清空后再插入。

种子编码是 `feat_care_alert_30d`、`feat_growth_traj_30d`。目录把所有 `status=1` 的 SKU 交给 App。新行没有 Apple 商品 ID 时，客户端买到它就会报商品不存在。

VIP 套餐编码固定，保存只更新那一行。功能套餐应对齐这个行为。

## Goals / Non-Goals

**Goals:**

- 空编码或未知编码拒绝，只更新已存在的 `feature_product` 行。
- 打开功能时表单带上原套餐编码。
- 去掉新建按钮。

**Non-Goals:**

- 不批量下架或删除已有 `fp_` 行。
- 不改 `product_code`，不改 App 建单请求结构。
- 不新增套餐种子。某功能本来就没有 SKU 时，保存失败并提示，不自动生成。

## Decisions

### 1. 服务端不再插入 SKU

`productCode` 去空白后为空：返回「须选择已有套餐，不能新建」。查无此行：返回「商品编码不存在，不能新建」。两者都不写库。

查到行则 `UPDATE` 价格、划线价、天数、数量、开通类型、Apple 商品 ID、上下架、所属功能、`updated_at`。`product_code` 不在 SET 里。

`genFeatureProductCode` 若不再被调用则删除。

### 2. 打开功能时选哪一条

当前功能的套餐列表中：优先 `status=1` 且编码不以 `fp_` 开头；否则任意上架；否则列表第一条。填入表单。列表为空则清空编码，保存会被服务端拒绝。

切换功能时用该功能的套餐覆盖表单，避免把上一个功能的编码存到当前功能。

### 3. 页面去掉新建

删除「新建套餐（清空编码）」按钮及其清空逻辑。说明文案改为：保存只改当前编码，不能新建。

## Risks / Trade-offs

- [已经上架的 `fp_` 行仍会出现在 App 目录] → 本次不自动下架；表单优先填种子编码，之后改价不会再新建。要下架须在列表里打开那一行再改状态，本次不强制。
- [某功能没有任何 SKU] → 无法从本页创建。现网两个付费功能已有种子行。

## Migration Plan

无表结构变更。部署后空编码保存开始失败。回滚恢复旧页面与插入逻辑即可，已更新的原套餐保留。
